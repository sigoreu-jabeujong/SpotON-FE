# 매출 분산 그래프·생활인구 카드 정리 (#99)

2026-11-16 사용자 최신 요청을 따른다. 계산 방식과 데이터 범위는 그대로 두고 제목을 **점포당 평균 추정 매출**로 표시한다. 중앙값 기준은 그래프 범례와 접힌 계산 기준에서 명시한다. 가중 참고평균/중복/월매출 미환산 문단과 금액의 `/점포`, 모든 참고 카드의 `(표시 반올림)`을 제거한다. 원문 금액/숫자 문자열은 변경하지 않는다. 생활인구와 주야간 제목의 `(행정동·내국인)` 및 포함동의 `· 검색 위치 포함`을 제거한다. 실제 반경 교차동의 관계 표시는 남긴다. 생활인구 출처에 원천의 행정동·내국인 범위를 유지한다.

생활인구 각 박스 안에 관측일24시간 시간당 평균 설명과 공식 출처 링크를 배치한다. 자료 없는 상태에도 같은 박스와 출처를 제공한다. 요청한 외국인/순방문객/반경 인구 부정 설명은 삭제한다. 주야간의 날짜·원천 일치 검증과 결측/0 구분은 유지한다.

## 그래프

- 서버 `per_store_average.distribution`의 중앙값·Q1/Q3와 같은 분기 included 항목의 `per_store_metric`을 사용한다. 가로축은 매출, 점 하나는 상권·업종 항목이다. 정규분포나 개별 가게 매출 분포를 추정하지 않는다.
- 선형 가로축에 실제 항목을 표시하고 중앙값은 점선, 중간50%범위는 연한 서비스 파랑으로 표현한다. 색으로 좋고 나쁨을 판정하지 않는다. 세로 배치는 점 겹침을 줄이기 위한 것으로 수치를 나타내지 않는다.
- Number 변환은 좌표와 눈금 표시용으로만 사용한다. 중앙값/분산/사분위 재계산, 이상치 제거, 새 집계/원자료 반올림은 없다. 선택 금액/중앙값 라벨은 서버 display 문자열을 그대로 사용하며 요청된 접미사만 제거한다.
- primary 분기·included 상태와 sample_count를 일치시킨다. 누락/비유한/음수/서로 다른 구성은 그래프 자료 없음으로 표시하고0점으로 만들지 않는다. 실제0만 있는 경우 중앙에 표시하고 '모든 항목0원'으로 안내한다.
- 4개 미만은 점과 중앙값만 표시하며 사분위 밴드·분산 수치는 숨긴다. 4개 이상에서 서버 분산 원값은 접힌 상세에 원² 단위로 제공한다.
- 점 hover/클릭/포커스로 정확한 금액을 확인한다. 차트 내 한 점만 Tab 순서에 두고 좌우/Home/End로 모든 점을 이동한다. 24px 선택 영역, 서비스 색상 토큰, 숫자 이외의 점/점선/밴드 범례를 제공한다. 종합·분석·PDF가 같은 컴포넌트를 사용한다.

#### 프로덕션 차단 사항

1. **키보드 좌/우 방향과 화면 방향 불일치.** 점 배열은 서버 `items` 순서 그대로이고 `ArrowRight`/`ArrowLeft`는 배열 인덱스로 이동한다. 금액 순 정렬이 없어서 오른쪽 키가 화면상 왼쪽 점으로 갈 수 있고, 끝에서 처음으로 순환해 Home/End와도 다르게 동작한다. 좌표값(동일 값이면 안정 정렬 키) 기준으로 정렬한 배열로 렌더링·탭 순서·세로 배치를 정하고, 순환 대신 양 끝에서 멈추는 방식을 권장한다. 렌더 순서 정렬은 표시 전용이며 통계 재계산이 아니다.
2. **단위 검증 없이 '원'/'원²' 고정 표시.** `per_store_metric.unit`, `median/q1/q3.unit`, `variance.unit`을 확인하지 않고 눈금에 `원`, 분산에 `원²`를 붙인다. 서버 단위가 `KRW_source_reported_per_store`(분산은 `..._squared`)가 아니거나 항목 간 단위가 섞이면 축과 분산 라벨이 사실과 달라진다. 단위가 모두 기대값일 때만 그래프를 그리고, 아니면 기존 "분포를 표시할 자료가 없어요"로 처리해야 한다.
3. **눈금 위치가 점 좌표와 맞지 않음.** 점 영역은 `mx-2` 안의 0–100%인데 눈금 줄은 `mx-2` 없이 `justify-between`이라 양 끝이 8px씩 어긋나고, '0원'은 왼쪽 정렬, 최대값은 오른쪽 정렬, 중간값은 글자 길이에 따라 위치가 달라진다. 눈금도 같은 `mx-2` 컨테이너에서 `left: 0/50/100%` 절대 위치 + 중심 정렬(양 끝은 경계 안쪽 정렬)로 두어 점·중앙값 선과 같은 기하에 맞춰야 한다. 360px 화면에서는 이 오차가 상대적으로 크다.
4. **좌표 문자열 파싱이 너무 관대함.** `Number()`는 `'0x10'`(16), `'1e3'`, `' 12 '`, `'0b1'` 같은 값을 받아들인다. 이런 값이 오면 서버 표시 문자열과 다른 위치에 점이 찍힌다. 좌표용 파싱 전에 부호 없는 십진수 정규식(예: `^\d+(\.\d+)?$`)으로 형식을 확인하고, 맞지 않으면 그래프 자료 없음으로 처리해야 한다. median/q1/q3/항목 모두 동일하게 적용한다.
5. **분위 표시 여부를 서버 플래그 하나에만 의존.** `hasSpread = !limited_reference_count`만 확인한다. 설계는 "4개 미만이면 숨김"인데 플래그와 `sample_count`가 어긋나면(예: 3개인데 false) 밴드와 분산이 노출된다. `sample_count >= 4 && !limited_reference_count`일 때만 보여야 하고, 둘이 모순되면 밴드·분산을 숨기는 쪽이 안전하다.
6. **그래프가 없을 때 중앙값 기준이 화면에 드러나지 않음(제목 승인과 별개인 표시 정확성 문제).** 제목은 승인대로 '점포당 평균 추정 매출'이고, 설계상 중앙값 기준은 그래프 범례와 접힌 상세에서 밝힌다. 그런데 표본수 불일치·비유한값·단위 문제로 그래프가 "자료 없음"이 되면 큰 숫자는 여전히 `distribution.median`인데, 중앙값이라는 사실은 접힌 `<details>` 안에만 남는다. 기본 상태의 PDF/인쇄에서는 이 내용도 보이지 않는다. 삭제된 문구를 되살리지 않는 범위에서, 그래프 실패 시에도 범례에 쓰는 짧은 '중앙값 기준' 표기 하나를 값 근처에 유지하거나, 그래프가 실패하면 차트 범례와 같은 기준 표기를 별도로 렌더해야 한다.
7. **PDF/인쇄에서 접힌 상세 누락.** 분산(원²)·Q1/Q3·계산 기준은 `<details>` 안에 있어 기본적으로 닫힌 채 인쇄·캡처된다. 그리고 선택 금액 줄은 첫 번째 점 하나만 출력된다. 설계 "종합·분석·PDF 같은 컴포넌트"를 지키려면 PDF 경로에서 details를 열린 상태로 렌더하거나(예: `open` prop 또는 print 전용 스타일), PDF에서는 선택 안내 문구("점을 선택하면…")와 단일 선택 금액을 숨기는 처리가 필요하다. 보고서 PDF가 print CSS 방식인지 캔버스 캡처 방식인지 확인한 뒤 결정해야 한다.
8. **시험 공백(설계 '검증' 항목 미충족).** 현재 시험은 `renderToStaticMarkup`만 사용하므로 키보드(Arrow/Home/End 포커스 이동), hover/클릭 선택, aria-live 갱신은 검증하지 않는다. `LocationReferenceView` 시험은 fixture 항목에 `average_contribution`/`per_store_metric`이 없어 정상 그래프가 그려지는 통합 경로를 한 번도 거치지 않는다(두 경우 모두 "자료 없음"). 단위 불일치, 16진/지수 문자열, 정렬된 키보드 순서, `sample_count`↔플래그 모순, 4개 이상 실제 0 + 밴드 폭 0 경우에 대한 시험을 추가하고, 360/390 모바일·키보드·PDF 확인은 실행 결과를 이 기록에 별도로 남겨야 한다.

#### 차단은 아니나 수정 권장

- 색상: 설계는 "서비스 색상 토큰"인데 코드는 Tailwind 기본 `blue-100/500/700`을 직접 쓴다. 프로젝트 토큰이 있으면 교체하고, 없으면 설계 문구를 실제 사용 색상에 맞춰 고친다.
- 겹침: 세로 배치가 `index % 7`이라 같은 금액의 점 i와 i+7이 완전히 겹쳐 포인터로 선택할 수 없다(키보드로는 가능). 항목이 많을 때는 정렬 후 값이 가까운 점끼리 세로 위치를 돌려 쓰는 방식이나 겹침 개수 표기를 고려한다.
- React key `market_code-industry_code-source_quarter`가 서버 중복 행에서 충돌할 수 있다. 인덱스를 보조 키로 붙인다.
- `onMouseEnter`마다 `aria-live="polite"` 영역이 바뀌어 포인터 이동만으로 스크린리더가 계속 읽을 수 있다. hover는 시각 강조만 하고, live 갱신은 포커스/클릭 때만 하는 쪽을 권장한다.
- 모든 점에 `aria-pressed`를 쓰면 토글 버튼 여러 개로 읽힌다. 단일 선택 의미라면 `aria-current` 등 다른 표현을 검토한다.
- 눈금 `tick()`은 compact 반올림 값(예: '1.5억원')으로, 정확한 금액 라벨이 아닌 축 표시다. 현재 설계 문구("Number 변환은 좌표와 눈금 표시용")와는 맞지만, 실제 브라우저에서 ko-KR compact 출력(만/억/조)을 확인해야 한다.
