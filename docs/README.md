# docs — Spot:ON 프론트엔드 정리 문서

> 마지막 갱신: 2026-11-10

이 폴더는 팀 산출물(PDF)과 BE 작업계획서를 **프론트엔드 개발에 필요한 만큼** 쉬운 말로 요약한 문서 모음이다.
원본 PDF·운영기관 자료·키 값은 저장소가 Public이므로 넣지 않는다. 여기에는 팀이 정리한 요약만 둔다.

| [api-contract.md](api-contract.md) | API 함수·타입·목업을 만들 때 | 공통 응답 형식, 공통 파라미터, 엔드포인트 9개, 열거값, 오류 코드, 명세서와 BE 작업계획서의 차이 |

## 기준 우선순위

자료끼리 다르면 아래 순서로 따른다.

1. **사용자(팀) 최신 결정** — [decisions.md](decisions.md)에 날짜와 함께 기록
2. **BE 작업계획서** — `SpotON-BE/docs/be-work-plan.md` (develop 브랜치)
3. **팀 산출물 PDF** — 06 API 명세서 v1.1, 07 데이터 활용 명세서 v1.1, 08 분석 로직 정의서 v1.0, 02 기능 명세서 등

- PDF와 BE 작업계획서가 다르면 **BE 작업계획서를 따르고**, 문서에 **"동기화 대기"** 라고 표시한다.
- 아직 정해지지 않은 값은 **"확인 대기"** 로 표시하고, 임시로 쓰는 기준은 **"FE 적용 기준"** 으로 적는다.
- API 필드·파라미터를 바꾸려면 명세서 수정 → FE·BE 합의 → 코드 수정 순서를 지킨다 (`CLAUDE.md`).

## 갱신 방법

- 기준이 바뀌면 해당 문서를 고치고 맨 위 "마지막 갱신" 날짜를 바꾼다.
- 결정이 새로 나면 [decisions.md](decisions.md)에 날짜와 함께 먼저 적고, 관련 문서를 따라 고친다.
