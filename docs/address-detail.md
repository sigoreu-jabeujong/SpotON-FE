# 주소·상세주소 확인과 같은 층 표시

사용자 승인 BE #202 / FE #94. 후보 선택만으로 이동하지 않고 선택 주소와 층·호를 확인한 뒤 확정한다. 주소·업종·상세·후보 변경과 unmount는 세대를 무효화해 이전 응답 이동을 막는다.

URL address는 기본 주소, floor는 BE 정상화값, detail은 입력 상세, detailMode=unverified는 명시적 미확인 계속이다. 입력 복원·조건 바·보고서·이미지는 공용 표시 함수를 사용한다. 미확인 원문은 판정값과 구분해 표시한다. 중복 키·상충 상세는 조회 전에 재확인을 요구한다.

공개 검증 후 #100에서 사이드바 진단 주소도 같은 공용 표시 함수로 맞췄다. API 요청의 기본 주소·좌표·건물키·AI 입력은 그대로 유지한다.

POST /api/address-detail은 키/DB/Kakao 없이 BE의 기존 층·호 파서를 실행한다. 모호한 복수층·동을 임의 보정하지 않는다. 이 경로는 목업에 응답이 없을 때 실제 BE로 전달된다. mock용으로 파서를 복제하지 않는다. 상세 없는 확정은 정규화 요청을 생략한다.

새 location_relation의same_floor는 지번 주소 범위 안의 명시 층 일치다. 같은 자리/실제 임차 공간/물리 건물 고유성의 확정이 아니다. 기존location_match·AI같은자리집계는 유지한다. 구BE/구응답은 기존 표시로 동작한다. 새 FE는 BE 정규화 API 배포 뒤 공개한다.
