## 최초 전체 화면 검수에서 발견한 동시 요청 문제

API 단독 및6개 동시 호출은 성공했지만 첫 전체 화면 검수에서는 DB 조회500이 발생했다. Render 로그에서 일반 조회의 약15초, 재시도하는 이력의 약30초 DB 연결 대기를 확인했다. 후속 전체 화면3흐름은 모두200이었으나 단일 연결 무료 환경의 요청 집중은 별도 보완한다. 배포 전환 중 ready 감시에서도500/502/네트워크 시간 초과가 있어 무중단 배포로 기록하지 않는다.

`src/api/databaseReadQueue.ts`는 DB를 사용하는 v2/v3 GET을 순서대로 전송한다. Web Locks 지원 브라우저는 같은 출처의 탭·보고서 프레임 간에도 순서를 공유하고, 미지원 환경은 페이지 내 대기열을 사용한다. 네트워크 제한 시간45초는 실제 전송 시 시작한다. 취소된 대기 요청은 전송하지 않으며 실패·취소 후 다음 요청을 진행한다. 주소 검색·상세 정규화·컨텍스트 발급·health·AI POST는 대기열 밖에서 처리한다. 서버 오류를 숨기는500 재시도는 추가하지 않았다.

서로 다른 사용자 간 부하는 이 브라우저 대기열로 제한되지 않으며 무료 서버의 처리 용량 자체가 증가하는 것은 아니다. 배포 후 운영 화면에서 다시 확인해야 한다.
